# Installed addon bytecode inventory

**Resolved in source, contract-tested on 2026-11-03.** The original frozen
metadata candidate is a24b14f3d241893e51703588f9db07a3a70cf11d and Rust
workflow 41730347088 remains failed; this repair does not rewrite its outcome.

## What

The native build/NumPy-floor stages pass, but all four installed-public smoke
jobs fail in `Validate the installed public runtime outside the checkout`.
The Python 3.14 job 126252211540 raises RuntimeError from
`validate_native_viewer_metadata`: its distribution inventory contains addon
`__pycache__/*.pyc` paths, rejected as retired/unreviewed files.

Source: [the original workflow](https://github.com/uibcdf/molsysmt/actions/runs/41730347088).
The source full matrix for this same frozen candidate has since passed all
eight lanes; these different gates keep their separate outcomes.

## How

The original `validate_installed_molsysmt.py` fed `distribution.files` directly
to the exact source/archive inventory check. All four native job logs now confirm
the same rejection, with the corresponding CPython 3.11--3.14 cache tags.

Original Linux wheel artifact 13277681656 contains no cache members and no
bytecode in its RECORD. Installing those unchanged bytes with pip 26.2.1 adds
25 addon caches to the installed RECORD, each without a hash or size. Both the
target-install metadata probe and a genuine prefix installation reproduce the
original validator failure. The wheel has 3,652 ZIP members and 3,425 original
RECORD entries; the target installation has 6,486 entries, including the 25
addon caches. These counts describe this exact artifact, not an invariant.

## Why

Archive payload and installer-generated files need different checks. This is
separate from #537's tar directory-entry classification defect. The failure
does not demonstrate an incorrect scientific kernel.

## Correction

Only the installed validator excludes exact `cache_from_source` names for the
current interpreter, at normal/opt-1/opt-2 optimization, when their reviewed
source is also present and the installed RECORD supplies neither hash nor size.
The shared source/archive allowlist and entry-point contract are unchanged.
Missing sources, retired or unreviewed files, foreign/nonstandard cache names,
archive-recorded caches and wrong entry points continue to fail. This is file
inventory classification, not bytecode authentication.
