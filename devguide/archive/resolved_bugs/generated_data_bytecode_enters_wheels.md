# Generated data caches enter locally built wheels

**Reported:** 2026-09-30, during installed-wheel validation for the plane kernel in uibcdf/molsysmt#265.
**Status:** Resolved; the actual rebuilt wheel and installed binary pass validation.

## What

A wheel built from the used checkout includes 29 bytecode files under
`molsysmt/data`. The installed-wheel validator rejects it before installation:

```bash
CARGO_NET_OFFLINE=true python -m pip wheel --no-deps --no-build-isolation --no-cache-dir --wheel-dir /tmp/molsysmt-plane-wheel .
python devtools/scripts/validate_rust_wheel.py /tmp/molsysmt-plane-wheel
```

The diagnostic is `wheel contains 29 bytecode/cache entries`.

## How

`tool.setuptools.package-data` includes `molsysmt.data = ["**"]` with no
package-data exclusions. This glob collects generated caches in source data
folders. `MANIFEST.in` excludes bytecode from the source manifest, but does not
filter this explicit wheel package-data glob. The fix adds global setuptools
package-data exclusions for bytecode and cache contents. Rebuild from a fresh
`build/` directory because already copied files can survive in a stale build.

## Why

Ordinary Python use can generate these untracked files. Local wheel delivery
then fails the existing binary-artifact gate even when the source and Rust
extension are valid. The repair must keep bundled scientific resources.

## Evidence and exclusions

**Reproduced:** 29 cache entries in the Linux wheel built from the dirty plane
checkpoint based on `7a8350f76`, Python 3.13.14. The rejection occurred before
loading the extension and is independent of plane-fitting accuracy.

**Contract-tested:** the guard calls setuptools' real package-data discovery with
the repository configuration. It creates nested and root caches and verifies
that H5MSM, compressed databases and JSON resources survive while caches do not.
The existing wheel validator still rejects a synthetic cache-contaminated wheel.
No runtime dependency or scientific format is changed.

## Acceptance criteria

- The source-data glob excludes cache and bytecode contents.
- Representative scientific resources remain discoverable.
- A rebuilt wheel passes archive and installed-extension validation.

## Provenance

2026-09-30, Linux x86-64 development environment, Python 3.13.14; build dependencies
are the installed setuptools, setuptools-rust and versioningit. No timing claim
is made by this report.

## Resolution — 2026-09-30

The new package-data exclusions remove all 29 cache entries while retaining the
279 non-cache entries under `molsysmt/data`. A fresh build is required to avoid
files previously copied into `build/`; source caches need not be deleted.
The regression exercises setuptools discovery with the real TOML settings,
including setuptools' wildcard-key normalization. The wheel archive validator
passes and the installed extension loads with its exact 101-export manifest and
MIC canary. A public plane smoke executes from outside the repository in a
separate non-editable environment with Angstrom input and explicit nm conversion.
This is local Linux/Python 3.13 evidence, not the supported-platform wheel matrix.

The rebuilt wheel SHA256 is
`c961a1f6c81a1edeb39b1724e0d35d0ff089ad53246dc987787d565b86edd295`.
It was produced from the dirty implementation checkpoint based on `7a8350f76`.
The packaging guard would fail if generated caches reenter data discovery or
if the broad exclusion accidentally drops the representative scientific resources.
