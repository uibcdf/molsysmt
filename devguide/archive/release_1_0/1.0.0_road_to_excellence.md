# Road to Excellence (Path to 1.0.0)

> **Archived plan:** This path-to-1.0 assessment is retained for history and does
> not define current priorities or completion status.

This document summarizes the strategic weaknesses and the specific requirements needed to transition MolSysMT from a solid functional library to an industry-standard production framework.

## 1. Strategic Weaknesses

### 1.1 Debugging Complexity (The "Decorator Onion")
The heavy use of stacked decorators (`@signal`, `@arg_digest`, `@dep_digest`, `@lazy_njit`) provides immense power but creates a high barrier for troubleshooting. 
- **Status**: [Mitigated] Standardized structured error context via `smonitor`.
- **Ongoing**: Maintain a clear separation between the "digestion" layer and "business" logic.

### 1.2 Memory Scalability (The Eager Loading Bottleneck)
MolSysMT previously operated mostly on an "in-memory" model for coordinates.
- **Status**: [Mitigated] The `molsysmt.basic.Iterator` and the internal Chunked Engine now provide a native "Out-of-Core" model.
- **Result**: The library can process massive trajectories without exceeding available RAM via chunked iterators over native and supported formats.

### 1.3 Change Fragility
Because of the highly modular and interdependent nature of the `form/` adapters, non-surgical refactors often have ripple effects in the conversion graph.
- **Mitigation**: Strict enforcement of Contract Testing and the adoption of `MolSysBuilder` for all new test fixtures.

## 2. Requirements for Excellence (Stabilization Checkpoint March 2026)

To declare version 1.0.0 "Rock Solid", the following tasks have been addressed or are in active development:

### 2.1 Elimination of "Bare Excepts" [COMPLETED]
All instances of raw `except:` clauses have been refactored to `except Exception as e:`.
- **Result**: Improved security by preventing the masking of system signals (`KeyboardInterrupt`) and easier debugging.

### 2.2 Advanced Observability and Debug Traceability [COMPLETED]
The library now supports deep introspection without user-facing noise.
- **DEBUG Signals**: Form validators and argument digesters now emit `MSM-DBG-PROBE-001` signals at `DEBUG` level when a detection fails.
- **Structured Error Context**: `ArgumentError` now captures the original exception as the `cause`, providing deep traceability.

### 2.3 Structural Hygiene and Resource Safety [COMPLETED]
- **File Descriptors**: Enforced context managers and explicit `.close()` in all handlers (H5, XTC, PDB, GRO, TRJPK, MSMPK). Native handlers now load content into memory buffers to avoid holding open files.
- **JIT Robustness**: Implemented explicit casting to `float64` for all inputs in `structure` and `pbc`.
- **Hierarchy Optimization (Dirty Bits)**: Implemented a state-tracking system in `molsysmt.Topology` to avoid redundant reconstructions of components, molecules, and entities.

### 2.4 High-Performance Coordinate Processing [COMPLETED]
- **Trusted Path**: Implemented a "Trusted Path" in `digest_coordinates` that bypasses PyUnitWizard for internal calls within `molsysmt.lib.structure` when data is already normalized.
- **On-Demand Alignment**: Refactored structural kernels to be unit-agnostic. Coordinates are kept in their original units (nm, Å, etc.), and unit alignment is performed only when comparing multiple systems, avoiding the "standardization tax."
- **Naked Arrays**: Ensured kernels receive raw `float64` NumPy arrays, maximizing JIT efficiency.

### 2.5 Stability Advisory System [COMPLETED]
- **Result**: Implemented `experimental_module` decorator using SMonitor `INFO` signals (`MSM-INFO-EXP-001`). Experimental modules like `molecular_dynamics` now automatically inform the user about their stability status.

### 2.5 Unified Diagnostic Catalog [COMPLETED]
- **Result**: Successfully migrated all critical native `ValueError` and `TypeError` to structured `smonitor.DiagnosticBundle` exceptions.
- **Coverage**: Updated 60+ validation points across `native`, `lib`, `build`, and `form` modules, ensuring deep traceability and automated caller identification.

### 2.6 Explicit Support Contract [PENDING]
- **Action**: Finalize the list of Tier 1 forms and modules that fall under the 1.0 stability guarantee.

## 3. The 1.0.0 Release Philosophy

**"Indestructible and Empathetic."**
- **Indestructible**: Mathematically identical results across all forms (Contract Testing), crash-proof kernels, and optimized hierarchical state management.
- **Empathetic**: Clear diagnostics, fast startup, and honest communication about experimental features.
