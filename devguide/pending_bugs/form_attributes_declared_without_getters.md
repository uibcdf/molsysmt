# Bug: forms declare attributes they cannot deliver

**Status:** Tier 1 resolved; Tier 2 and Tier 3 remediation pending
**Severity:** medium — remaining debt is outside the contractual Tier 1 surface
**Locations:** `molsysmt/form/*/attributes.py`, getter modules, and pipe metadata

## Problem

Some adapters declare an attribute `True`, but neither expose a getter compatible
with the attribute catalog nor provide a usable topological or structural pipe.
The single-attribute pipe-selection defect has been fixed separately, so the
remaining entries are declaration or adapter-delivery debt rather than a routing
false negative.

When no valid delivery route exists, `get()` now raises a catalog-backed
`NotWithThisFormError` instead of leaking a raw `AttributeError`. That makes the
failure professional and diagnosable; it does not make the declaration truthful.

## Executable inventory

The source of truth is generated by:

```bash
python devtools/scripts/validate_form_adapters.py
```

The audit checks every `attributes=True` declaration against:

- catalog-compatible direct getters;
- the relevant pipe for a single topological or structural request;
- a callable or lazy-string converter to the pipe target;
- the target form's declaration and transitive delivery path;
- pipe cycles.

Attributes with no `get_from` entry are exempt because the public facade cannot
request them directly. Registered derivations count as delivery routes. Mechanical
attributes otherwise require direct delivery because current `get()` piping only
partitions topological and structural attributes.

The accepted debt is encoded compactly in
`devtools/data/form_attribute_delivery_baseline.json`. The initial 2026-07-13
baseline contained 882 unreachable declarations across 70 forms. The same pass
removed 18 false Tier 1 `bond_id` claims and implemented a shared derivation
route for 60 box-derived declarations, leaving 804 declarations across 58 forms.
A subsequent targeted pass implemented sequence-group getters, direct
`file:xyznpy` coordinate access, and the missing system-level connectivity
catalog routes. A second native-data pass implemented deterministic atom-index
delivery for coordinate-only structures and trajectory readers, leaving 790
declarations across 49 forms. Completing optional native structure fields,
NetworkX connectivity getters, and `MolSys` mechanical delegation reduced the
checkpoint again to 780 declarations across 45 forms. PDBFixer's two source-PDB
metadata claims were then retracted because the PDBFixer object does not retain
those fields, leaving 778 declarations across 44 forms. Activating verified
topological and structural pipes for ten Tier 1 adapters, completing the
`openmm.State` getters, and fixing current OpenMM GROMACS recognition removed a
further 258 violations. The final Tier 1 pass implemented native CHARMM CRD
delivery, optional PSF boxes, thermodynamic series in native Structures and
MolSys objects, and OpenMM Context/Simulation runtime metadata. It also removed
claims for data that the source objects do not retain. This reduced the current
checkpoint to 489 declarations across 29 forms, with zero Tier 1 violations.
The curated scientific-validation pass subsequently restored direct structural
delivery for MDTraj HDF5 files, while other post-quick-win adapter work resolved
additional baseline entries. Direct CHARMM CRD atom-count delivery brings the
validator to 430 declarations across 29 forms, 59 fewer than the quick-win
checkpoint, with Tier 1 still at zero.
These are dated checkpoints, not normative counts: the validator reports
the current total and fails only when the current set is not a subset of the
baseline.

Do not maintain a second manual form-by-form table here. It became stale as soon
as tiers and lazy converters were audited explicitly.

## Remediation policy

For each baseline entry, first determine whether the declared intention can be
implemented from data native to the form or through a semantics-preserving
conversion. Prefer implementation over reducing the declared capability. Choose
one evidence-backed remedy:

1. **Implement a shared derivation** when the attribute can be computed from an
   already deliverable source attribute.
2. **Declare a pipe** when conversion is the canonical, semantics-preserving
   delivery route.
3. **Implement a getter** when the attribute is native and direct access avoids
   unnecessary conversion.
4. **Set the declaration to `False`** only when the required information is not
   present, cannot be reconstructed without inventing semantics, and no valid
   conversion route exists.

Adding a pipe is not automatically correct. Verify conversion availability,
selection and structure-index behavior, shape, units, IDs, `None` semantics, and
lossiness using a representative object. Broad adapters such as
`parmed.Structure`, `rdkit.Mol`, and `MDAnalysis.Universe` are explicit Tier 3
forms; they remain important debt, but Tier 1 remediation has priority.

## Prioritization

1. Tier 2 contractual claims.
2. Tier 3 forms, starting with cheap truthful-declaration corrections before
   expanding adapter functionality.

## Acceptance criteria per form

- The form's violation set is a strict subset of its baseline set.
- Representative public `msm.get()` calls pass for each retained declaration.
- Tests cover selection, structure indices, shape, units, and `None` behavior as
  applicable.
- Removed declarations are reflected in the User Guide and course material if
  they were publicly documented.
- The baseline is regenerated only to remove resolved bits, never to accept new
  debt.
