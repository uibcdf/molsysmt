## Context and Purpose
This document provides a critical, in-depth audit of MolSysMT's current state as it approaches the `1.0.0` milestone. This is not just another minor release; **`1.0.0` represents a shift from "experimental utility" to "production-grade scientific infrastructure."**

This audit evaluates MolSysMT both as a standalone library and as the orchestrator of the UIBCDF ecosystem (`smonitor`, `depdigest`, `argdigest`, `pyunitwizard`). It is written to be explicit and actionable for developers joining the stabilization effort.

---

## 1. The Flexibility Paradox (Public API Stability)
MolSysMT's greatest strength is its ability to accept almost any object as a `molecular_system` (files, trajectories, topologies). 

**The Sprint Outcome: Contract Testing Success**
- **Identity Verified**: We have implemented **Contract Tests** that assert identical results for `get` and `select` across Native, MDTraj, and OpenMM.
- **Visual Parity**: MolSysViewer and NGLView are now recognized as valid molecular systems, allowing direct introspection of the view state.

## 2. The Glass Ceiling of Code Coverage
The current `implementation_plan.md` sets a coverage goal of >= 75%. For a core infrastructural library, this is insufficient.

**The 1.0.0 Mandate: 90% Core Coverage**
- Core modules (`molsysmt/basic`, `molsysmt/native`, `molsysmt/element`, `molsysmt/form/native`) must reach **>= 90% coverage**.
- Integration modules (`thirds` and obscure file parsers) can remain at lower coverage, but the mathematical and structural core must be heavily tested.

## 3. The Labyrinth of Forms (Adapter Maintenance)
Maintaining dozens of adapters for third-party libraries (MDTraj, OpenMM, ParmEd) is a heavy burden.

**The Sprint Outcome: Support Tiers Locked**
We have classified forms into explicit support tiers:
- **Tier 1 (First-Class):** Guaranteed parity (Native, MDTraj, OpenMM).
- **Tier 2 (Hardened):** Stable and hardened during the sprint (MDAnalysis, RDKit, BioPython, MolSysViewer).
- **Tier 3 (Niche):** Pytraj, NetworkX, and obscure formats.

## 4. Total Ecosystem Integration (The "AI-Ready" Goal)
MolSysMT is the flagship consumer of the UIBCDF infrastructure.

**The Sprint Outcome: 100% Alignment**
- **SMonitor:** All core exceptions migrated to the catalog. `caller` enforcement is universal.
- **ArgDigest:** All functions in all forms (even delegates) are now wrapped with `@arg_digest`.
- **DepDigest:** Zero top-level imports of soft dependencies.
- **PyUnitWizard:** Physical units are standardized across all 60+ converters.

## 5. The Hidden Startup Cost (Lazy Loading decision)
**The Sprint Decision: String-Based Registry**
To achieve instantaneous `import molsysmt`, we have transitioned all `_convert_to` dictionaries to use **strings** instead of function pointers. This prevents Python from loading submodule code until the exact conversion is needed.

## 6. Persistence & The "Native" Source of Truth
**The Sprint Outcome: Handler Robustness**
- **Polymorphic Handlers**: `H5MSMFileHandler` and `PDBFileHandler` now handle path-to-object instantiation automatically during conversion, but keep the responsibility separated from the scientific logic.
- **H5MSM Versioning**: Next step is adding version metadata to the `.h5msm` format.

## 7. Documentation as Code (Notebook CI)
- [ ] **Automated Notebook Execution**: Final step for 1.0.0 is integrating all tutorials into the CI pipeline.

## 8. Selection Language Homogeneity
- **Selection Identity Verified**: Identical selection strings return identical indices across all Tier 1 forms.
