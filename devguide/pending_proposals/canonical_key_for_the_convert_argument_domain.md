# Canonicalizing the key of `convert`'s argument domain

**Status:** proposed, deliberately deferred. **Filed:** 2026-08-08.
**Depends on:** an addition to ArgDigest (`Domain(key=...)`), not on MolSysMT alone.

## What is already done

`molsysmt.basic.convert` declares a delegating domain: `Domain(depends_on='to_form',
by_value=CONVERTER_ARGUMENTS)`, with the table written out in
`molsysmt/_private/argdigest/domain/converter_arguments.py` and regenerated by
`devtools/scripts/generate_converter_arguments.py`. A mistyped converter keyword is
refused with `UnknownArgumentError` and a near-miss suggestion.

## The gap

`convert` accepts two ways of naming a file target, and both are supported on purpose:

```python
msm.convert(molsys, to_form='file:pdb', output_filename='traj.pdb')   # the documented idiom
msm.convert(molsys, to_form='traj.pdb')                               # the shorthand
msm.convert(molsys, to_form=Path('traj.pdb'))                         # and as a Path
```

The contract is checked before digestion, so the domain sees the raw value. `'file:pdb'`
is a key in the table and the domain applies. `'traj.pdb'` is not a key of anything -- the
form is only resolved inside `convert`, at `convert.py:34-38` -- so the domain returns
"cannot decide" and the call is left unchecked.

## Why it was not fixed now

Measured, not assumed: the shorthand is **not** a silent-wrong-answer path. `convert`
forwards its keywords to a converter with a closed signature, so Python itself catches the
mistake:

```
TypeError: to_file_pdb() got an unexpected keyword argument 'output_filenam'. Did you mean ...
```

The diagnostic arrives later and carries no catalogue code, but it arrives. What this
proposal buys is **uniformity of diagnosis**, not correctness. That is worth doing and not
worth rushing.

Related and already verified as needing nothing: `to_form='file:pdb'` without
`output_filename` raises `NotCompatibleConversionError` naming the missing attribute. That
rule is conditional on a *value*, which is exactly what a function contract must not
express, so it stays where it is.

## What it would take

**1. ArgDigest: `Domain(depends_on=..., by_value=..., key=<callable>)`.** The callable
canonicalizes the raw value before the lookup, identity by default. This is not specific
to MolSysMT: any consumer whose users can spell a key in more than one way -- different
capitalization, an alias, a path standing in for a type -- has the same gap.

The rule to document alongside it, which is what keeps the mechanism honest:

> The key must be a function of the **argument value as given** -- string and scalar work.
> Never of the data that value points to.

That is the line that makes canonicalizing `to_form` legitimate and deriving `from_form`
from the molecular system not: the first is bounded, the second is not.

**2. MolSysMT: a name-to-form resolver in `molsysmt/form/`.** Not in
`_private/argdigest` -- it is a missing piece of the form vocabulary, not a private
workaround, and the domain should point at it the way the `attribute` domain points at
`molsysmt.attribute`.

```python
get_form_from_name('traj.pdb')       # 'file:pdb'
get_form_from_name('file:PDB')       # 'file:pdb'
get_form_from_name('openmm.Topology')# 'openmm.Topology'
get_form_from_name('nothing.zzz')    # None -- names no form; the caller has the better diagnostic
```

It answers a different question from `molsysmt.basic.get_form`, which asks "what form is
this *object*?" and must interrogate the detectors to find out. Here the input is only a
name, so the answer is a catalogue lookup plus the naming convention for file forms.
Measured at **0.56 us** against **529 us** for `get_form` before its optimization -- and it
is also *more correct* for this use, since `get_form('file:pdb')` raises, as it should:
that string is a name, not a pdb file.

Two details the implementation must not miss, both found by looking at the existing tests:

- `PurePath` inputs, which `is_file` already handles and a naive `isinstance(x, str)`
  guard would silently drop -- reintroducing the very gap this closes.
- Compound extensions. `file:bcif.gz` is a real form, so taking the text after the last
  dot is not enough.

**3. `is_file` should then lean on it.** `is_file('traj.pdb')` currently falls through to
`get_form`, paying the whole detector sweep. With the resolver in place it becomes a
lookup. So this adds no second source of truth -- it removes duplicated work from the one
that exists.

## Order

ArgDigest first (1), since without it (2) has no consumer. Both are small; neither blocks
1.0.
