# Rust and Numba Divergence Contract — Historical Migration Evidence

> **This contract governed a comparison that no longer runs.** It belongs to
> Segment B of the 1.0 execution plan, which is `DONE`; Numba was removed in
> Segment D and there is no second backend to diverge from. The document is
> retained because it is the record of *which* Numba behaviours the Rust port
> deliberately refused to reproduce, and why — the justification behind several
> deliberate divergences that are now simply the shipped behaviour.
>
> Where a divergence corrected a genuine upstream defect, the corresponding bug
> report is archived under
> [`archive/resolved_bugs/`](archive/resolved_bugs/) with a note on where the
> correct behaviour now lives and which test guards it.
>
> The closing two-backend comparison is preserved in
> [`release_1_0_final_numba_oracle_artifact.md`](release_1_0_final_numba_oracle_artifact.md).

## Original purpose

Numba was the temporary migration oracle for the Rust-only MolSysMT runtime.
Agreement with that oracle was required where the Numba behavior was defined and
scientifically correct. Blind equivalence was not required where Numba had an
unsafe edge case, violated the public contract, or produced a scientifically
incorrect result.

The generated artifact
`devtools/data/rust_numba_divergences.json` records that boundary explicitly.
It is generated by
`devtools/scripts/audit_rust_numba_divergences.py` and must not be edited
directly.

## Commands

Checking the committed artifact:

```bash
python devtools/scripts/audit_rust_numba_divergences.py
```

Requiring every policy and divergence to be accepted:

```bash
python devtools/scripts/audit_rust_numba_divergences.py --require-closed
```

Inspecting or intentionally regenerating the artifact:

```bash
python devtools/scripts/audit_rust_numba_divergences.py --json
python devtools/scripts/audit_rust_numba_divergences.py --write-manifest
```

The closed audit runs in smoke CI. A missing parity policy, an implicit NumPy
tolerance, a missing referenced test, a provisional decision, or a stale
artifact fails the gate.

## Explicit Tolerances

Every `numpy.allclose` and `numpy.isclose` call in the 14 parity modules must
declare both `rtol` and `atol`. This is essential because NumPy otherwise uses
a default relative tolerance of `1e-5`, even when a test appears to request a
strict absolute tolerance.

The B3 audit found 63 comparisons with an implicit relative tolerance. After
setting `rtol=0.0` where a relative tolerance was not deliberately part of the
contract, the complete Rust surface still passes. The generated artifact now
freezes 77 explicit closeness sites. Changing, adding, or removing one makes
the artifact stale and requires review.

An absolute tolerance is not evidence by itself. Each parity module therefore
has a recorded basis, such as:

- measured FMA or fastmath accumulation differences;
- distinct, valid eigensolvers;
- an independently rebuilt covariance or inertia matrix;
- brute-force wide-shell minimum-image ground truth;
- algebraic or geometric invariants;
- exact comparison of integer membership, offsets, and ordering.

## Accepted Deliberate Divergences

Eight deliberate divergences are accepted:

1. Rust corrects triclinic minimum-image wrapping for vectors outside the
   primitive cell.
2. Rust produces complete triclinic neighbor sets against a wide-shell
   all-pairs oracle.
3. Rust corrects the orthogonal-box branch selection used by SASA.
4. Rust honors the documented structure-axis broadcast for periodic dihedral
   editing instead of reading outside the Numba array.
5. Rust returns valid empty series results instead of performing an unchecked
   first-element access.
6. Rust canonicalizes principal-axis eigenvector signs.
7. Rust canonicalizes PCA signs and permits a different valid basis in a
   degenerate eigenspace.
8. The private coexistence seam normalizes the mutating Numba and
   value-returning Rust Rodrigues helpers to one return contract.

Each entry records the Numba behavior, Rust behavior, decision, tolerance,
executable tests, and evidence. These are not general permissions to diverge.
Any new difference requires a new reviewed entry and independent
justification.

## Must-Match Contracts

Some surfaces are protected as exact contracts:

- orthogonal periodic wrapping and classification;
- ties-to-even handling of exact half-box jumps;
- integer series and topology outputs;
- neighbor membership and CSR structure where both backends are valid.

Floating neighbor distances have their own absolute envelope; the integer
membership does not.

## Mathematical Nonuniqueness

Eigenvectors require special treatment:

- `v` and `-v` describe the same axis;
- a degenerate eigenspace admits multiple valid orthonormal bases;
- eigenvalues remain comparable within the recorded spectral envelope;
- isolated eigenvectors can be compared up to sign;
- degenerate vectors must instead satisfy the defining eigen-equation and
  orthonormality.

Canonical Rust signs improve reproducibility but must not be confused with a
different scientific result.

## Interpretation of Closure

B3 closure means:

- every current parity module has an accepted policy;
- every closeness assertion declares its full tolerance;
- every known deliberate divergence is classified and evidence-backed;
- exact contracts remain explicit;
- no provisional decision remains;
- the complete Rust and selected scientific-truth suites pass.

It does not mean the final migration campaign has run. B4 must execute the
reproducible two-backend comparison over the declared matrix. B5 must preserve
its environment, commands, results, and commit as the dated final Numba-oracle
artifact.
