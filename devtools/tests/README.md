# devtools/tests toolbox

Local toolbox for running tests, analysing coverage, tracking history, and
uploading reports to Codecov. Run all `make` targets from this directory.

```bash
cd devtools/tests
make help   # full target + variable reference
```

---

## Quick start

```bash
make test              # full suite, no coverage (~10 min on 14 cores)
make coverage          # full suite + terminal report + coverage.json + coverage.xml
make coverage-open     # full suite + HTML report opened in browser
make smoke             # smoke tier only (~4 tests, <5 min)
make weekly            # full suite + coverage.xml + junit.xml  (mirrors CI)
```

---

## All targets

### Test execution

| Target | Description |
|--------|-------------|
| `make test` | Full suite + doctests. `peptide_parity` tests auto-deselected. |
| `make coverage` | Full suite with terminal report + `coverage.json` + `coverage.xml`. |
| `make coverage-html` | Full suite with HTML report in `htmlcov/`. |
| `make coverage-open` | Same as `coverage-html`, then opens `htmlcov/index.html`. |
| `make coverage-json` | Force fresh run: deletes `coverage.json` and regenerates it. |
| `make slowest` | Show slowest pytest items (`DURATIONS=25`). |
| `make smoke` | Smoke tier (~4 tests). Mirrors `ci-smoke.yaml`. |
| `make weekly` | Full suite + `coverage.xml` + `junit.xml`. Mirrors `ci-weekly.yaml`. |

### Coverage analysis

All analysis targets reuse an existing `coverage.json` if present (prints a
notice). Use `make coverage-json` to force a fresh run first.

| Target | Description |
|--------|-------------|
| `make coverage-hotspots` | Lowest-coverage files. `HOTSPOT_TOP=15`, `SUBPACKAGE=` |
| `make coverage-packages` | Aggregate by subpackage. `PACKAGE_DEPTH=1` |
| `make coverage-top` | Total (depth 0) then depth-N breakdown. |
| `make coverage-map` | Hierarchical textual map. `MAP_DEPTH=2`, `SORT=coverage\|name` |
| `make coverage-markdown` | Generate `coverage_summary.md` + `coverage_summary.json`. |
| `make coverage-diff` | Compare current `coverage.json` against `BASELINE_FILE`. |
| `make coverage-check` | Validate against thresholds in `coverage_thresholds.json`. |
| `make coverage-history` | Append current summary to `coverage_history.json`. |
| `make coverage-history-report` | Print last N rows from history. `LAST=10` |

### Module/test association

| Target | Description |
|--------|-------------|
| `make module-test-map` | JSON map of modules → associated test files. |
| `make module-test-gaps` | Print modules with no associated tests (heuristic). |

### CI pipeline (local)

```bash
make ci NPROC=12   # coverage.json → markdown → check → history → module-map
```

### Codecov upload

```bash
CODECOV_TOKEN=<token> make upload-codecov
```

Requires `coverage.xml` to exist (run `make weekly` first) and the
`codecovcli` package (`pip install codecov-cli`).

See **Manual Codecov upload** section below for the full procedure.

### Cleanup

```bash
make clean   # removes htmlcov/, .coverage, coverage.json, coverage.xml,
             # junit.xml, and summary files.
             # coverage_history.json is intentionally kept.
```

## Key variables

| Variable | Default | Description |
|----------|---------|-------------|
| `NPROC` | `14` | Workers for `pytest-xdist` |
| `DIST_MODE` | `loadfile` | `pytest-xdist` distribution mode |
| `PACKAGE` | `molsysmt` | Package passed to `--cov` |
| `TEST_DIR` | `../../tests` | Unit test root |
| `DOCTEST_DIR` | `../../molsysmt/basic` | Doctest source root |
| `HOTSPOT_TOP` | `15` | Number of hotspot files shown |
| `PACKAGE_DEPTH` | `1` | Subpackage depth for coverage-packages / coverage-top |
| `MAP_DEPTH` | `2` | Depth for coverage-map |
| `CODECOV_TOKEN` | _(empty)_ | Codecov upload token |
| `CODECOV_SLUG` | `uibcdf/molsysmt` | Repo slug for Codecov |

## Manual Codecov upload

This procedure uploads a local coverage report to Codecov without waiting for
the weekly CI run.

### Requirements

- `codecov-cli` installed: `pip install codecov-cli`
- The org-level Codecov token stored in LastPass under `"codecov/token"`
- `coverage.xml` generated by `make weekly` (not `make coverage`)

### Step-by-step

**1. Run the full suite with coverage from the repo root**

```bash
make weekly
```

This generates `devtools/tests/coverage.xml` with repo-root-relative paths
(required by Codecov for correct file mapping).

**2. Push any pending commits to GitHub**

Codecov must be able to find the commit on GitHub.

```bash
git push
```

**3. Upload**

```bash
CODECOV_TOKEN=$(lpass show --password "codecov/token") make upload-codecov
```

The upload target runs `codecovcli upload-process` with:
- `--sha` auto-detected from `git rev-parse HEAD`
- `--branch` auto-detected from `git rev-parse --abbrev-ref HEAD`
- `--git-service=github`
- `--network-root-folder=.` (to normalise absolute paths in the XML)
- `--disable-search` (only uploads `coverage.xml`, no other files)

**4. Verify**

The command prints a URL like:

```
https://app.codecov.io/github/uibcdf/molsysmt/commit/<sha>
```

Open it to confirm the report was processed. Allow ~30 seconds for Codecov to
finish processing.

### Why `make weekly` and not `make coverage`?

`make coverage` runs pytest from `devtools/tests/`, which can produce absolute
paths in `coverage.xml`. `make weekly` runs from the repo root, so paths are
always relative to the repo root as Codecov expects.

### Token storage

Store the token in LastPass and retrieve it on demand:

```bash
# Store (one-time):
lpass add "codecov/token"   # enter token in the Password field

# Use:
CODECOV_TOKEN=$(lpass show --password "codecov/token") make upload-codecov
```

## Notes

- `peptide_parity` tests are auto-deselected at collection time by
  `tests/conftest.py`. To run them explicitly:
  ```bash
  pytest -m peptide_parity tests/build/build_peptide/test_build_peptide_molsysmt_MolSys.py
  ```
- `coverage_history.json` is intentionally excluded from `make clean` — it is
  a persistent record of coverage evolution over time.
- Module/test association matching is heuristic. Use it to spot missing test
  files quickly, not as a proof of full coverage.
