# Lazy Loading

Lazy loading is a fundamental design principle in MolSysMT that defers reading heavy array data from disk or memory until it is explicitly requested by a calculation or query.

---

## The Big Data Challenge

Molecular trajectories generated by modern simulation packages can occupy tens or hundreds of gigabytes. Traditional structural biology packages frequently attempt to parse and load entire coordinate arrays into RAM upon opening a file, leading to memory saturation, sluggish startup times, or out-of-memory crashes when working on laptops or shared workstations.

---

## Metadata-First Initialization

When opening a trajectory file or initializing a supported native handler (such as `file:h5msm`), MolSysMT performs **metadata-first initialization**:

- **Topological Indexing**: Atom names, residue groups, chains, and entity hierarchies are parsed and cached.
- **Trajectory Footprint**: Total frame count, timestep intervals, and array dimensions `(n_structures, n_atoms, 3)` are registered.
- **Deferred Coordinates**: Heavy 3D coordinate arrays remain on disk in optimized binary formats until required.

---

## Streaming and On-Demand Fetching

Because heavy arrays are accessed on demand, operations that only inspect topological metadata (such as counting atoms, filtering selections, or querying sequence identities) execute instantaneously with near-zero memory footprint.

When structural coordinates are needed for calculation, streaming file handlers (such as `molsysmt.H5MSMFileHandler`) fetch only the requested frame indices, supporting seamless streaming over large trajectory datasets.
